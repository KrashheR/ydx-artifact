# Гейм-дизайн ревью: «Найди отличия: Архив аномалий»

Дата: 2026-07-19. Основа: `docs/game_concept.json`, текущая реализация (`src/shared/store/gameStore.ts`, `src/shared/lib/progression.ts`, `src/content/*`, `src/screens/*`), README.

Цель ревью: оценить сильные и слабые стороны и дать план доработок для роста удержания (D1/D7), возвращаемости и коммерческого успеха на Яндекс Играх и CrazyGames.

---

## 1. Общая оценка

Это редкий для веб-порталов случай «find the differences» с настоящей продуктовой основой: связный нарратив, коллекционная мета, аккуратная монетизация, дисциплина по UX (без энергии, без жёстких таймеров, no-dead-end правила). Качество исполнения вертикального среза высокое.

Главный риск — **контентный потолок и слабый повод возвращаться**. Игрок, которому игра понравилась, проходит 39 уровней за 2–4 сессии и упирается в стену: daily из 7 повторяющихся сцен, streak без эскалации наград, отсутствие целей после финала. Для порталов, где алгоритмы продвигают игры по возвращаемости и длине сессии, это критично.

Вердикт: **ядро — 8/10, retention-слой — 4/10, монетизация — 5/10, платформенная готовность (Yandex) — 8/10, (CrazyGames) — 2/10.**

---

## 2. Сильные стороны

1. **Нарративный каркас поверх казуальной механики.** Пре/пост-тексты уровней, сквозная тайна трёх экспедиций, артефакты-улики — это дифференциатор: 95% конкурентов в жанре — голые пары картинок. Работает на «ещё один уровень» внутри сессии.
2. **Комфортная модель без наказаний.** Нет энергии, жизней, таймера в кампании; misclick снижает точность, но не отнимает ресурсы. Это правильный выбор для аудитории 25–60 и для модерации Яндекса.
3. **Дисциплина монетизации.** Interstitial только с victory-экрана по CTA «следующий уровень», не при возврате на карту; rewarded — по явному запросу подсказки. Низкий риск отписки от рекламы и жалоб модерации.
4. **Техническая зрелость.** Cloud save с merge-правилами, save после каждого найденного отличия, аналитика по всем ключевым событиям, data-driven контент со схема-валидацией, dev-редактор хитбоксов. Это дешёвые итерации контента в будущем.
5. **Чёткая система «звёзд» (accuracy → 1–3 звезды)** — уже есть основа для replay-мотивации, хоть она пока не эксплуатируется.
6. **Onboarding по best practice:** новый игрок сразу попадает в уровень 1 с мягким оверлеем, без регистрации и меню-лабиринта.

## 3. Слабые стороны

### 3.1 Retention/возвращаемость (критично)

- **Daily — 7 сцен по `dayNumber % 7`.** Через неделю игрок видит повторы. Daily — главный инструмент D7/D30, а здесь он исчерпывается за 7 дней. Награда за daily — всегда +1 лупа, без вариативности.
- **Streak считается, но не награждает по эскалации.** Концепт обещает day1=1 лупа, day2=2 лупы, day3=косметическая рамка; в коде — только инкремент счётчика и +1 лупа за daily. Streak без растущей ценности не создаёт страха потери — основного драйвера возвращаемости.
- **Нет endgame.** После 39 уровней `getNextCampaignLevelId` возвращает `null` — и всё. Нет ни «идеального прохождения» как цели, ни нового режима, ни тизера следующей кампании.
- **Звёзды не имеют смысла.** Лучший результат хранится, но ни на что не влияет: нет счётчика «звёзд всего», нет наград за 3★, нет гейтов и витрины. Replay-мотивация нулевая.
- **Коллекция пассивна.** 15 артефактов открываются автоматически по прогрессу — их нельзя «упустить» и не за чем возвращаться. Коллекция — экран просмотра, а не система целей.
- **Нет причин для второй сессии в день** и нет механик «вернись завтра, чтобы…» кроме daily.

### 3.2 Монетизация

- **IAP «Архивный набор» из концепта не реализован** (в `src/services` нет purchase-кода). Отключение interstitials за деньги — самый честный и конверсионный оффер для этой аудитории, и его нет.
- **Rewarded — только 1 плейсмент** (подсказка в уровне). Концепт закладывал ещё post-level bonus magnifiers и recover missed daily — не реализованы. Лупы при этом щедро сыпятся из прогрессии (+1 за каждые 2 уровня), что подрывает спрос на rewarded.
- **Экономика луп не сходится:** приток (прогрессия + daily) стабильно превышает расход у аккуратного игрока → к середине второй кампании подсказки девальвированы.

### 3.3 Сессия и сложность

- **Нет кривой сложности как системы.** Уровни различаются числом отличий, но нет управляемого нарастания (размер/контраст отличий, зум-обязательные детали). Риск: опытному игроку скучно к 20-му уровню.
- **Find-ALL модель** (нужно найти все отличия, все хитбоксы обязательны) без таймера — уровень нельзя «пройти хуже/лучше» по полноте, только по accuracy. Это сужает пространство результатов.
- **Мобильный portrait заблокирован** гейтом «поверни устройство». Концепт прямо требовал A/B-toggle для portrait как самостоятельный UX. На Яндексе большая доля мобильного трафика — portrait-гейт срезает конверсию первой сессии заметной части аудитории.

### 3.4 Платформы

- **CrazyGames не поддержан вовсе:** адаптер только Yandex + mock; нет CrazyGames SDK (init, ad calls, happytime, invite/link), нет портальной локали (CG — глобальная аудитория, дефолт должен быть EN, а не RU-fallback).
- **Нет лидербордов** — обе платформы дают их бесплатно (Yandex Leaderboards API; на CG — хотя бы внутренние). Для «точности и скорости» это естественная соревновательная ось.

## 4. Рекомендации

Приоритет P0 — до/сразу после релиза, максимальный эффект на удержание; P1 — первые 2–4 недели liveops; P2 — стратегические.

### P0 — Возвращаемость и повторное использование готового контента

1. **Daily из кампании, а не из 7 сцен.** Ротировать daily по всему пулу пройденных кампаний с ежедневным модификатором: «найди за N минут» (мягкий таймер уже в концепте), «без подсказок», «зеркальная сцена» (horizontal flip — дёшево, а сцена ощущается новой). 7 архивных сцен оставить как «особые дела» по выходным. Это превращает 39+7 сцен в месяцы daily-контента без нового арта.
2. **Реализовать эскалацию streak по концепту** (1 лупа → 2 лупы → рамка → далее цикл с редкими бонусами на 7/14/30 днях) + экран «серия под угрозой» при заходе после пропуска + rewarded «восстановить серию» (заодно новый ad-плейсмент из концепта).
3. **Дать звёздам смысл.** Счётчик суммарных звёзд на хабе; за пороги (13★/26★/39★… по кампании) — награды: лупы, рамки компаратора, «печати архива» на карте. Экран результатов должен показывать «до 3★ не хватило X% точности — переиграть?». Это включает replay готового контента.
4. **Endgame-заглушка.** После 39 уровней: экран «Дело открыто» с тизером 4-го меридиана, целью «собрать все 3★» и «пройти все 7 архивных дел». Пустой финал — прямая потеря D7+.
5. **Portrait-режим на мобильных** (A/B toggle из концепта) вместо rotate-гейта — иначе теряется первая сессия значимой доли мобильного трафика Яндекса.

### P1 — Монетизация и сложность

6. **Реализовать IAP «Архивный набор»** (отключение interstitials + 5 луп + рамка, цена из Yandex catalog). Показывать оффер контекстно: после 2-го просмотренного interstitial, ненавязчиво.
7. **Добавить 2 rewarded-плейсмента из концепта:** post-level «удвоить/получить лупы» на victory-экране (самый конверсионный момент) и восстановление пропущенной daily-награды.
8. **Сбалансировать экономику луп:** прогрессионный приток снизить (+1 за 3 уровня вместо 2) или сделать поздние уровни объективно сложнее, чтобы спрос на подсказки рос вместе с притоком.
9. **Формализовать кривую сложности в контент-пайплайне:** метаданные уровня (мин. размер хитбокса, требуемый зум, контраст) + валидация. Акт 1 — крупные отличия, акт 4 — «зум-обязательные». Скорость прохождения контента упадёт, глубина сессии вырастет.
10. **Опциональный «режим экспедиции» (timed) для пройденных уровней** — мягкий таймер, отдельная награда. Не трогает комфорт кампании (pillar «комфорт важнее наказания» сохранён — режим строго опциональный).

### P2 — Платформы и социальность

11. **CrazyGames-адаптер:** отдельный platform adapter (SDK init, midgame/rewarded ads, `happytime()` на victory, portal locale → дефолт EN, отключение Yandex-специфики: review prompt, метрика). Архитектура `src/services` это уже позволяет — усилия умеренные. Для CG критичны: быстрый first input (<10 сек), EN-качество текстов, отсутствие RU-only ассетов.
12. **Лидерборды Яндекса:** «звёзды всего» и еженедельный борд по daily-времени. Дёшево, даёт соревновательную ось и плейсмент в UI платформы.
13. **Четвёртая кампания как liveops-цель.** Пайплайн levelgen уже есть (`scripts/levelgen/*`) — планировать выпуск «нового дела» раз в 6–8 недель; тизерить в endgame-экране (см. п.4).
14. **Лёгкая социальность без бэкенда:** шаринг результата daily (время+точность) через платформенные share API; на CG — invite link.

## 5. Ожидаемый эффект (гипотезы для проверки аналитикой)

| Мера | Метрика | Ожидание |
|---|---|---|
| Daily из полного пула + модификаторы | D7 | значимый рост: daily перестаёт исчерпываться за неделю |
| Streak-эскалация + recover | D1→D7 конверсия | рост за счёт loss-aversion |
| Смысл звёзд + endgame-цели | сессий/пользователя, replay rate | рост повторных прохождений готового контента |
| Portrait-режим | конверсия первой сессии (mobile) | снятие rotate-гейта уберёт ранний отвал |
| IAP + 2 rewarded | ARPU | рост без давления на UX |
| Кривая сложности | среднее время уровня, hint usage | контент «живёт» дольше, спрос на лупы растёт |

Существующая аналитика (`level_complete` payload, hint/rewarded события) покрывает проверку всех гипотез — новых событий почти не нужно (добавить: `replay_start`, `daily_modifier`, `streak_recover_offer/claim`).

## 6. Что НЕ надо делать

- Не добавлять энергию, жизни, вторые валюты, battle pass — это ломает позиционирование «уютной архивной тайны» и pillar-ограничения концепта, а аудитория 25–60 чувствительна к агрессивному F2P.
- Не ставить жёсткий таймер в кампанию — только опциональные режимы.
- Не увеличивать частоту interstitials ради краткосрочного дохода — на Яндексе рейтинг игры напрямую влияет на трафик.
