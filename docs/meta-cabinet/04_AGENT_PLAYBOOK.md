# 04 — Плейбук агентной разработки (Codex + Claude)

Как довести мету до релиза только силами агентов. Оператор (человек) запускает сессии, принимает решения на гейтах тиров и делает коммиты/пуши.

## 1. Роли агентов

| Роль | Кто | Задачи | Входные документы |
|---|---|---|---|
| **Дизайнер-ревьюер** | Claude | Уточнение дизайна систем, тексты RU/EN, ревью UX, приёмка тиров | `01_VISION_AND_SYSTEMS.md`, `game_concept.json` |
| **Архитектор** | Claude | Save v3 + миграции, схемы контента, декомпозиция задач тира на сессии | `02_TECH_ARCHITECTURE.md`, `SAVE_SCHEMA.md` |
| **Кодер-фичи** | Codex или Claude | Реализация slice/экранов/оверлеев по одной задаче за сессию | `02_TECH_ARCHITECTURE.md` + карточка задачи из `05_PROGRESSION_TIERS.md` |
| **Контент-агент** | Claude | `boardGraphs`, `ranks`, `mapFragments`, тексты, i18n | `03_ART_AND_CONTENT_PIPELINE.md` |
| **Арт-агент** | Codex/Claude + levelgen | Промпты и прогон `scripts/levelgen`, маски слоёв, оптимизация | `03_ART_AND_CONTENT_PIPELINE.md` |
| **QA-агент** | Claude | Тест-планы, e2e (Playwright), регресс существующих флоу, прогон DoD-чеков | `05_PROGRESSION_TIERS.md` (DoD тира) |

Практическое правило: Codex — на изолированные кодовые задачи с чёткой спецификацией (один модуль, один PR); Claude — на всё, где нужны дизайн-решения, тексты, кросс-файловые изменения (save+store+UI) и ревью.

## 2. Железные правила (усвоенные на этом репозитории)

1. **Одна задача — одна сессия — один коммит.** Начало сессии: `git status` чистый. Конец: DoD-чеки + коммит. Не оставлять uncommitted-работу «на потом» — в этом репо уже теряли работу через `git checkout --` без просмотра diff.
2. **Никаких параллельных сессий над пересекающимися файлами.** `gameStore.ts`, `schema.ts`, `common.json` — самые конфликтные файлы; задачи, трогающие их, идут строго последовательно. Параллелить можно только: контент-модуль ↔ UI-компонент ↔ docs.
3. **Кириллица — только UTF-8.** Codex-сессии ранее портили кириллицу в docs (cp1251). Проверка после каждой сессии, редактировавшей RU-тексты: `git diff` не должен показывать кракозябры; писать файлы явно в UTF-8.
4. **Не править чужие ожидания тестов.** Если существующий тест упал — это сигнал регресса, а не повод «поправить тест»; эскалация оператору.
5. **Строки — только через i18n**, геометрия — только в `hitTesting.ts`, платформа — только через `src/services` (правила CLAUDE.md/AGENTS.MD действуют для всех агентов).
6. **Каждая сессия завершается обновлением `05_PROGRESSION_TIERS.md`** (чекбоксы + строка в журнале). Это единственный механизм передачи контекста между агентами и сессиями.

## 3. Шаблон промпта кодовой сессии

```text
Контекст: прочитай docs/meta-cabinet/README.md, 02_TECH_ARCHITECTURE.md (раздел N)
и карточку задачи Tx.y в 05_PROGRESSION_TIERS.md. Ничего сверх карточки не делай.

Задача: <одно предложение из карточки>.

Ограничения:
- Не трогай файлы вне списка карточки.
- Все новые строки в обе локали (ru + en), UTF-8.
- Чистые функции — в src/shared/lib с юнит-тестами.
- Существующие тесты должны проходить без изменения ожиданий.

Definition of Done:
- pnpm lint && pnpm typecheck && pnpm test && pnpm validate:content — зелёные.
- Обновлены docs по правилу CLAUDE.md (SAVE_SCHEMA/CONTENT_PIPELINE при затрагивании).
- В 05_PROGRESSION_TIERS.md проставлен чекбокс Tx.y и добавлена строка журнала.
Отчитайся: что сделано, что НЕ сделано, какие файлы изменены.
```

## 4. Шаблон промпта арт-сессии

```text
Прочитай docs/meta-cabinet/03_ART_AND_CONTENT_PIPELINE.md (раздел «ассеты Tx»).
Сгенерируй <ассет> через scripts/levelgen в каноне visualDirection из docs/game_concept.json:
без текста в изображении, без лиц, палитра paper/ivory/teal/ochre/brass.
Прогони pnpm assets:optimize, добавь записи в ASSET_MANIFEST.md и ASSET_PROVENANCE.json.
Выведи 2-4 варианта на выбор оператору, не выбирай сам.
```

## 5. Гейты между тирами

Переход к следующему тиру — только после ручной приёмки оператором:

1. QA-агент прогоняет DoD-чеклист тира (в `05_PROGRESSION_TIERS.md`) и пишет отчёт.
2. Оператор смотрит билд руками (`pnpm dev`, unlock-чит из README) по сценарию приёмки тира.
3. Дизайнер-ревьюер (Claude) делает UX-ревью против `01_VISION_AND_SYSTEMS.md` и анти-требований.
4. Коммит-тег `meta-tier-N-done`.

| T2 Кабинет MVP | 4–6 | 2–3 | 2 |

Итого до релиза меты (T0–T4): ~25–35 агентских сессий.
